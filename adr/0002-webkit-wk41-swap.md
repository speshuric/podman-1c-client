# ADR-0002: webkit2gtk 4.1 вместо 4.0 (подмена бандлов на .wk41)

**Статус:** принят (действителен и на ubuntu:24.04 — webkit 4.0 там
тоже отсутствует; легко поломать при смене версии платформы —
проверять наличие `.wk41`).

## Контекст

Ubuntu 24.04 и 26.04 несут только webkit2gtk **4.1** (libsoup-3). Пакет
`libwebkit2gtk-4.0-37` отсутствует. Дистрибутив 1С 8.3.27.2342 бандлит
UI-библиотеки, собранные под webkit **4.0** (`libwebkit2gtk-4.0.so.37`,
`libsoup-2.4.so.1`, `libjavascriptcoregtk-4.0.so.18`), и рядом — варианты
`.wk41` под webkit 4.1.

Затронутые файлы (в `/opt/1cv8/x86_64/<версия>/` и `libwx` в
`/opt/1cv8/common/`):

- `libwx_gtk3u-3.0.so.0.1.0` ↔ `libwx_gtk3u-3.0.so.0.1.0.wk41`;
- `webkit2_extu-3.0.so` ↔ `webkit2_extu-3.0.so.wk41`.

## Решение

При сборке образа подменяем основные имена на `.wk41` варианты
(оригиналы сохраняем с суффиксом `.wk40`). Браузер/HTML-поле работает
через webkit2gtk-4.1 из apt.

## Почему так

- Собрать webkit 4.0 из исходников ради одного API — огромный пласт
  (webkit старой ветки не собирается новым компилятором без патчей).
- Платформа сама предоставляет совместимые сборки `.wk41` — это
  поддерживаемый 1С путь.
- Проверено: тонкий клиент стартует, webkit2gtk-4.1 замапится в процесс
  (5 маппингов в /proc/<pid>/maps), хелперы WebKit*Process на месте.

## Риски / TODO

- При смене версии платформы проверить, что `.wk41`-файлы есть в
  дистрибутиве (если 1С выпилит их — решать по-новой: apt-пакет webkit4.0
  из старого релиза Ubuntu или self-build).
- Полный тест HTML-поля переносится в приёмку (нужна лицензия и база).
