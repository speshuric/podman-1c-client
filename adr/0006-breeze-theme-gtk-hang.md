# ~ADR-0006: Breeze-тема для GTK-диалогов 1С и ловушка «окно не мапится»~

**Статус:** отвергнут. Теория «зависание из-за отсутствующей темы»
опровергнута; костыли удалены из скрипта запуска. Причина зависания —
не тема (см. ADR-0007).

## Контекст (что утверждалось ранее)

Считалось, что диалоги 1С рисуются через GTK3 с хостовой темой Breeze,
а «окна процессов создаются (200x200), но не мапятся» — из-за
`gtk-theme-name=Breeze` в `settings.ini` при недоступной теме в
`~/.local/share/themes`. «Лечение» — симлинки темы + копирование
`settings.ini` в том home при каждом старте контейнера.

## Опровержение

Изолированные прогоны (без остальных факторов) воспроизвели зависание
с пустым home, без `settings.ini` и без Breeze; и, наоборот, полноценный
контейнер с тем же профилем работал. Влияние темы не подтвердилось.

Фактическая причина зависания — базовый образ ubuntu:26.04 (ABI-связка
GTK/wxGTK в новом релизе; точный механизм не установлен). После смены
базы на ubuntu:24.04 окна мапятся штатно без каких-либо Breeze-костылей
(ADR-0007).

## Решение

- `breeze-gtk-theme` из образа убран, копирование `settings.ini` и
  симлинки темы из `bin/1c-run.sh` убраны.
- Файловые диалоги 1С остаются системного GTK-вида. Попытка включить
  нативные KDE-диалоги через портал (`GTK_USE_PORTAL=1`, host dbus)
  не сработала: платформа показывает собственный GTK-диалог (ADR-0008).

## Урок

Гипотеза не проверялась изолированно: изменение темы внедрялось
одновременно с другими правками, «успех» приписан теме. Одна гипотеза
за раз, возврат к предыдущему состоянию при неудаче.
